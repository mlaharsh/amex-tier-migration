# Model card — Amex Premium Card Tier Migration & Margin Optimization

## Model details

- **Task:** Binary churn classification + per-tier margin optimization
- **Selected model:** Logistic regression
- **Pipeline:** `ColumnTransformer` (OneHotEncoder + StandardScaler) → `LogisticRegression`
- **Features:** 26 engineered features (see `docs/data_dictionary.md`)
- **Tiers:** No-Fee, Silver, Gold, Platinum, Centurion
- **Decision threshold:** tuned on out-of-fold cross-validation predictions to maximize F1; evaluated once on holdout
- **Training data:** synthetic Amex-style portfolio (25,000 customers)
- **Holdout:** 20% stratified split (~5,000 customers)

## Intended use

- Portfolio-level prioritization: which customers to target for tier migration (upsell/downsell) or retention outreach.
- Margin awareness: expected annual margin per tier informs whether a migration is economically justified.
- Internal decision support for card product and retention teams.

## Not intended for use

- Credit underwriting, pricing, or eligibility decisions.
- Causal inference: a recommended migration does not guarantee margin improvement.
- Real customer data without first replacing the synthetic portfolio and re-validating.

## Evaluation metrics (holdout)

| Metric | Value |
| --- | --- |
| ROC-AUC | ~0.82 |
| Precision | ~0.60 |
| Recall | ~0.70 |
| F1 | ~0.65 |
| Brier score | ~0.17 |

Exact committed values are in `models/metrics.json` and `reports/evaluation/test_predictions.csv`.

## Training procedure

1. Generate/load `data/raw/card_portfolio.csv`.
2. Split 80/20 stratified on `Churn`.
3. Cross-validate 5-fold on training split; tune threshold to maximize F1 on out-of-fold predictions.
4. Fit final pipeline on all training rows.
5. Evaluate once on holdout; serialize `models/card_tier_model.joblib`, `models/metrics.json`, `models/feature_importance.csv`, and `reports/evaluation/test_predictions.csv`.

Run:

```bash
python -m card.train --generate-data
```

## Bias and fairness considerations

- **Income and credit score** are features and correlate with tier assignment. Subgroup performance should be audited before customer-facing use.
- **Gender and region** are included for completeness; they must not drive credit, pricing, or eligibility decisions.
- No protected-class targeting is implemented; all recommendations are margin- and risk-driven.

## Deployment

- **Native Streamlit app:** reads `models/card_tier_model.joblib`; no secrets required; runs locally, in Docker, or on Streamlit Community Cloud.
- **Browser scorer:** client-side JavaScript implementation generated by `python -m card.browser_export`; runs on GitHub Pages; no backend, no persistence; portfolio demo only.
- The static GitHub Pages site and scorer are **not** a production decision endpoint.

## Monitoring checklist

- Score distribution and alert rate by tier.
- Calibration and Brier score on labelled outcomes when they arrive.
- Margin lift realization for customers who actually migrate.
- Drift in spend, utilization, delinquency, and credit score distributions.
- Subgroup performance and complaint/opt-out rates.

## Retraining

Retrain with `python -m card.train --generate-data` when data or decision policy changes. Review generated `reports/evaluation/` and commit new artifacts together.
